03context-engineering

Context engineering.

一个可靠的 Agent 不只是需要更大的 context window，还需要控制哪些内容进入上下文、历史如何演进，以及项目资源何时加载。Xoder 将这些能力放在可检查、可替换的边界上。

01

AGENTS.md

项目指令可以从用户目录、父目录和当前项目加载，使同一个 harness 在不同代码库中获得不同工作方式。

02

Compaction

接近 context limit 时自动总结较早的消息，并保留近期对话与继续任务需要的信息。也可以使用 /compact 主动压缩；发生 context overflow 时，Xoder 会尝试压缩并继续。

03

Skills

Skills 将专门指令和工具说明组织成按需加载的能力包，不需要把所有内容永久塞进 system prompt。

04

Prompt templates

可复用的 Markdown prompt，通过 /name 形式展开，并支持参数替换。

05

Dynamic context

Python extensions 可以处理输入、观察 lifecycle events、拦截工具调用与结果，并向当前工作流发送自定义消息。

04session-history

Tree-structured,
durable history.

会话以可读的 JSONL 记录持久保存。你可以回到过去的节点创建分支，恢复已有会话， 或导出完整记录，而不需要丢掉原来的路径。

/tree选择历史节点
prompt tool call new branch continue
/resume 恢复会话 /export 导出 HTML / JSONL
05ways-to-run

Three modes.

Interactive

进入完整的 Textual TUI，在同一场会话中查看流式回复、调用工具、切换模型， 并恢复或继续已有的会话历史。适合需要持续协作和人工控制的日常工作。

Print / JSON

使用 xoder -p "query" 直接执行脚本、自动化流程和一次性任务； 使用 -o json 输出结构化事件流，方便交给其他程序继续处理。

SDK

安装 xoder-ai 后，从 xoder_agent 导入 AgentHarness 与 AgentHarnessConfig，组合自己的 Provider、 模型、工具和事件监听器，把可复用的 Xoder agent loop 嵌入 Python 应用。

06make-it-yours

Replace the parts.
Keep the contract.

Xoder 不把 Agent 固定成一个产品。替换 Provider、工具、工作流或界面时， 核心消息和事件边界仍然保持清晰。

  • PROVIDER 接入新的模型协议
  • TOOLS 注册自己的异步工具
  • WORKFLOW 扩展技能、命令与生命周期
  • INTERFACE 使用 TUI、脚本或自己的前端
